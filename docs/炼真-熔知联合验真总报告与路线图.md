## 一、我们到底在解决什么问题

炼真（Albedo）对单条视频/文档抽"主张(claims)"，你反馈**"抽出的主张本身没意义"**。经研究，根因是：

- 验真轴把两件事混为一谈：**"可被核查"(check_worthy)** 和 **"值得知道"(有认知负载)**。
- 系统其实已有"有意义抽取"路径（`core/merit.py`：核心洞见/可复用步骤/差异点/坑/适用场景/迁移成本），但**验真轴没消费它**，只抽"任何可检验的事实陈述"——教程里每句话都 check_worthy，却少有跨上下文仍有价值的知识。

三件事的状态：

| 代号 | 内容 | 状态 |
|------|------|------|
| A | Layer2（字幕作语料）降级为"忠实度门"，不再写 accuracy 循环抬高 trust_score（避免 x=x） | **已落地**（三文件改完，工作区未提交） |
| B | 主张"没意义"= 验真轴抽错目标（抽叙述重述而非有价值陈述） | **已拍板：现在做方案1（最小改动），方案2/3 进路线** |
| C | 跨源矛盾/支持检测（让主张在多源碰撞中显价值） | **本就是熔知设计意图**，确认不变 |

> 真正解法（深层）= 让主张进入**多源碰撞**（C，熔知跨源收敛真值）；作为最小起步，先以**方案1 升级抽取提示词**改善"有意义抽取"，方案2/3 留作后续增强（见路线图 #15/#16）。

## 三、关键研究结论

### 3.1 OSINT / 事实核查工具（已成熟，未来直接接）
混合事实核查范式 = 知识图谱 + LLM + 检索智能体。

| 工具 | 用途 | 可用性 |
|------|------|--------|
| Wikidata | 3 亿+ 实体结构化事实源 | 公开 API |
| ProVe | 基于 Wikidata 的事实验证，带 Web API | 开源 |
| FEVER | 185K 声明事实核查基准 | 公开 |
| FactNet | 1.7B 跨语言 事实↔证据 图 | 研究 |
| aiFactCheck | 模块化开源事实核查管线 | 开源 |

→ 优先接 Wikidata/ProVe 类**结构化事实源**，比 LLM 自由联网更稳、可溯源。

### 3.2 多信源互证（深研）
- **多源知识融合** = 冲突检测 + 实体对齐 + 真相发现。
- **Nari 框架**：来源可靠性 ↔ 事实真伪 **互相推断、迭代收敛**（可靠源说的更可信；它说可信的，反过来证明它可靠）。
- **MultiRAG**：多来源建"线图"，分**图级 + 节点级**两级置信过滤杂音。
- **信源互指网络**：跨平台互相引用 → 置信度**指数级**上升。
- **投票机制**：多个独立可靠源支持同一事实 → 采纳；冲突显式标"待验证"。

### 3.3 单轴五级信源（**最终采用模型**）
你拍板：不用北约双轴（太复杂），改用**单轴五级**——按"离原始/客观多远"排，**数字越大越不可信**。

| 级 | 类型 | 例子 | 可信度 |
|----|------|------|--------|
| 1 | 原始数据 / 论文 | 一手观测、实验数据、同行评审论文 | 最高（事实基准） |
| 2 | 聚合平台 | Wikidata、权威数据库、维基、行业库 | 高（已结构化/策展） |
| 3 | 新闻媒体 | 官媒 / 市场化媒体 / 行业媒体 | 中（编辑过，需交叉核） |
| 4 | 自媒体 / 社交平台 | 个人账号、公众号、论坛、短视频 | 低（仅作线索） |
| 5 | 主观观点 / 传言 | 个人看法、匿名爆料、无出处猜测 | 极低（默认干扰项） |

> ③ ④ 为你忘记档，上表为 AI 补位（③ 新闻媒体 / ④ 自媒体社交），**待你确认**。
> 对熔知意义：5 档映射到现有 `SOURCE_CONFIDENCE`(file/rule/llm/user) + `source_quality`(#21b) 机制（无需新字段）。高 tier（1–2）权重高、可单独采信；低 tier（4–5）只作线索。

### 3.4 熔知版本升级（已读代码确认现状）
- 当前 `doc_manager.py` 为**覆盖更新**（重摄入 upsert 新块并删旧版孤儿块），**无版本历史**。
- 你要的"已入库文件版本升级 + 追踪历史 + 差异比对"是**新功能**（设计版本表 doc_id + version + parent_version + diff）。
