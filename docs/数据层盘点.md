# 数据层盘点：五器 + 鲜管家数据地图

> 来源：Odoo 统一真相源思路借鉴报告（2026-08-04 调研，doc_de6206b75f35d387）
> 定位：架构决策的"宪法"级文档——统一哪些、独立哪些、为什么。蓝图对应模块见 [BLUEPRINT.md](../BLUEPRINT.md)「数据层：谁管哪本账」。

## 一、三类数据总览

| 类别 | 定义 | 特征 |
|------|------|------|
| **总账（唯一真相源）** | 知识本体，全系统只有一份权威出处 | 丢失 = 知识永久损失；任何模块要用知识必须查这里 |
| **台账（本器状态）** | 各模块自己的运行状态，不含知识正文 | 丢失/清除 = 只丢状态，知识无损；可重建 |
| **临时杂物（缓存）** | 下载原始文件/中转/日志/备份 | 用完即清，清了无任何影响 |

## 三、统一三原则

1. **知识只进总账（熔知）** — 任何"知识正文"（要长期保存、可检索、可溯源的内容）必须入熔知，禁止散落各器自存一份
2. **状态只记台账（本器）** — 各器自己的运行状态（队列/审批/技能/接单）记本器台账，台账清空不影响知识
3. **杂物随时可清（缓存）** — 下载原始文件/中转/日志/备份一律视为可清，禁止依赖

## 四、反例（禁止行为）

- ❌ 在行动清单/任何台账里复制知识正文（应只存 doc_id 引用）
- ❌ 各器自建"第二个知识库"（如炼真/凝华私自存结构化知识副本）
- ❌ 把台账当知识总账长期依赖（台账删了要能接受）

## 五、新增模块时的归属流程

1. 问：这数据是"知识正文"还是"状态"还是"临时"？
2. 知识 → 进熔知（Qdrant）
3. 状态 → 本器开台账（json 记账本，模式参照 action-flow）
4. 临时 → 随便放，标注可清
5. 拿不准 → 先按"状态/临时"处理，不默认开新总账
