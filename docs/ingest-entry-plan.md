## 二、整体架构（文字图）

```
         ┌───────────── 巨作（薄壳）─────────────┐
         │  ① 输入路由   ② 三器独立启停   ③ 统一日志 │
         └───────┬──────────────┬───────────────┘
        B站URL   │              │  file / note
           │     │              │
     ┌─────▼──┐  │        ┌─────▼─────┐
     │ 馏析    │  │        │ 筐② inbox  │←─ 熔知 watcher 捡走入库
     │ queue  │  │        └───────────┘
     └───┬────┘  │
     产出 → 筐①  │
     ┌───▼────┐  │
     │ 炼真    │  │  （两个监控文件夹 = 唯一耦合，已是现成设计）
     │ watcher│  │
     └───┬────┘  │
     产出 → 筐②  │
     ┌───▼────┐  │
     │ 熔知    │  │
     │ watcher│  │
     └────────┘  │
```

**核心**：巨作不编排流程，只做"投递 + 启停 + 看日志"。三器各自读文件夹、写文件夹、各跑各的。

## 三、完整任务清单

### 模块 A：巨作薄壳入口（新建 OpusMagnum 代码，MVP 必须）

| 任务 | 落点文件 | 做什么（大白话） |
|------|---------|----------------|
| **A1** 分类路由 | `front_half/ingest_router.py`（新建） | 一个 `route()` 函数：B站地址→展开 b23.tv→`nigredo 入队`；文件→白名单(md/pdf/txt/png/jpg)写收件箱；笔记→生成标准头 .md 写收件箱；**非B站链接→拒收**。网页和对话入口共用此函数 |
| **A2** AI 投递箱 | `front_half/drop_watcher.py`（新建） | 轮询 `drop/inbox_drop/*.json`，捡到→调 route→**立即删 json**；坏 json 移走不阻塞；单线程顺序处理（天然防串） |
| **A3** 网页入口页 | `app.py`（Streamlit 加页） | URL/文件/笔记三输入 + 提交即刷一次看"已接收" + 队列概览卡 + 三器状态灯 + 日志页（手动刷新+尾部200行） |
| **A4** 三器启停 | `front_half/supervisor/launcher.py`（新建/扩） | 启动/停止按钮，拉起 馏析消费/炼真/熔知；PID端口防重复；**关巨作不杀三器** |
| **A5** 日志汇聚 | launcher.py | 把三器 stdout 重定向到 `logs/<项目>.log`，用 RotatingFileHandler（5MB 切、留最近3）—三器内部零改 |

### 模块 B：馏析队列加固（改 Nigredo，MVP 必须，运行优先瘦身版）

| 任务 | 落点文件 | 做什么（大白话） |
|------|---------|----------------|
| **B1** 三态+锁+去重 | `core/queue.py` | 队列状态 `pending/processing`（**不写无限 done 记录**）；读写加文件锁防半写损坏；同地址去重 |
| **B2** 常驻+单消费者 | `run_queue.py` | 从"开机 drain 一次"改**常驻循环**：有地址就跑馏析→产物落筐①→取下一个；启动前 PID 去重，**绝不双开**（防同地址被两进程各处理一次=串） |
| **B3** 成功才移除 | `core/queue.py`+`run_queue.py` | 只有确认馏析产物已落筐①（下游能捡），才把该地址从队列删。**绝不 drain 就清空**，崩溃不丢项 |
| **B4** 失败重试 | `run_queue.py` | 地址 404/限流 → 简单重试，**不引入重型死信区**（运行优先，保持简单） |

> 馏析**不学**熔知的心跳看门狗/完整状态机——地址处理快，用不上，加了反而可能引入 bug。

### 模块 C：缓存区管理（确认不改，仅标注现状，零新代码）

| 任务 | 现状 | 决策 |
