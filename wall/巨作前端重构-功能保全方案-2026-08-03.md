## 三、防 BUG 策略（核心）

### 规则 1：业务函数零改动
`route_bilibili / route_file / route_note / launcher_start_all / launcher_stop_all / start_service / stop_service / fetch_dashboard_docs / set_starred / is_starred / check_all / get_all_repo_summaries / get_all_tasks / _doc_row / _on_toggle_star / dashboard_body / CONTENT_TYPE_LABELS / week_bounds / qdrant_reachable` —— **一个字符都不动**。只动：
- `build_left_drawer()`（删，换顶部条函数 `build_top_bar()`）
- 4 个页面函数的"壳"部分（`build_left_drawer(...)` 调用行 → `build_top_bar(...)` 调用行）
- `/wall` 页删除
- 其它一律不碰

### 规则 2：分步执行 + 每步真实浏览器验证
| 步骤 | 做什么 | 验证点（真实浏览器截图/操作） |
|---|---|---|
| 第 1 步 | 新增 `build_top_bar()` 顶部条函数（含页签/系统状态/外链），先**不动**抽屉，两套并存 | 顶部条显示正确 |
| 第 2 步 | 4 个页面改调 `build_top_bar`（去掉抽屉），业务区零改动 | 周看板/摄入/总指挥逐页操作：收藏、上传、启停、日志全正常 |
| 第 3 步 | 删 /wall 页 + 顶部条加"总指挥部"链接（跳 Dashy） | 显示墙从 Dashy 打开正常；巨作无循环嵌套 |
| 第 4 步 | Dashy 侧收编 5 工具卡片（按门户化方案） | workspace 内嵌 + 快捷键 + 状态点 |
| 第 5 步 | 逐项对照"功能保全清单"打勾验收 | 31 项全 ✅ |

> 每步完成后 git commit，任何一步出问题 `git revert` 回滚，**不会累积坏状态**。

### 规则 3：验收即"31 项逐项打勾"
重构完成后，按本方案第一节的 31 项清单逐项核对（打开页面 → 操作 → 确认），任何一项缺失 = 不通过，回滚或补齐。

### 规则 4：视觉降级不做"顺手优化"
本次只做"换壳"，**不顺手改样式/不顺手重构业务代码**——减少改动面 = 减少 BUG 面。样式想优化单独列一轮（可选后续）。
