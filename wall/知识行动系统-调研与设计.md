# 知识→行动回流系统：竞品调研与完整设计

> 版本：v1.1 | 日期：2026-08-03 | 状态：✅ MVP 已实施（2026-08-03 18:10）

## 一、竞品逐个分析（11 个）

### 1. KimiClaw 知识管理（OpenClaw 生态）⭐最相似
- **是什么**：月之暗面基于 OpenClaw 封装的云端 AI 智能体，定时任务 + 长期记忆 + 技能市场。
- **核心工作流**：①告诉它长期目标（职业/产品/成长）+ 决策原则 → ②每天早上 8 点按目标自动策划 4-5 项任务 → ③Next.js 看板三列追踪（待办/进行中/已完成）→ ④晚 8 点定时总结订阅邮件。
- **优点**：目标驱动（不是"有什么推什么"，而是"按目标策划该做什么"）；总结后询问用户评价、更新偏好（越用越准）；多端可用。
- **缺点**：依赖 Kimi 云生态、数据上云；通用知识管理不针对特定路线；每天粒度太碎，无"知识缺口→收集方向"闭环。
- **启发**：①目标层先行——先把用户目标写死，提炼行动时优先匹配目标；②三列看板。

### 2. CLI-Workboard（工作副脑，Trae 生态 Demo）
- **是什么**：CLI 专属工作看板，14 个功能面板，面向一人公司/超级个体。
- **核心工作流**：文档蒸馏（上传文档 → AI 提炼关键认知+决策依据+行动项）→ 并行看板四列（需求→开发→验收→完成）→ 晨报（6 源情报+解读）→ 三重记忆晋升（短期→长期→Wiki）。
- **优点**："文档蒸馏"概念与馏析几乎同名——产出三段式（认知+依据+行动项）非常实用；战略地图（OKR→KR→Agent）结构清晰。
- **缺点**：Demo 未成熟；通用职场场景，非定向路线。
- **启发**：①行动项提炼的三段式格式；②看板四列（需求→开发→验收→完成）。

### 3. Personal Panopticon（个人全景监狱）
- **是什么**：Claude Code + Obsidian 全套个人 AI 工作流，FLUX 三层架构（方向→系统→杠杆）。
- **核心工作流**：每天早上输入"开工"→ AI 自动跑 8 步（回顾昨天/查目标进度/同步项目/拉日历/扫邮件/抓热点/建今日清单）→ 任务标四色：🟢建议行动（同意就执行）/🟡备好选项（我来挑）/🔴亲自处理/⚪今天不动 → 每周 WAM 周会（上週完成率+**该调什么**的策略校正）。
- **优点**：三个原则与蓝图完全一致——**数据集中、AI 分析、人做决策**；行动分级四色极实用；周会不只报"做得不够"还报"该调什么"（根因分析）。
- **缺点**：重度依赖 Claude Code + 大量自定义，复制成本高；多 AI 并行成本高。
- **启发**：①行动分级四色（建议/备选/亲办/不动）；②周会做策略校正而非只报数字。

### 4. Obsidian + Codex 周复盘
- **是什么**：Telegram 速记机器人 + Codex 每日简报 + 每周复盘。
- **核心工作流**：每日早 6 点自动读近 24h 新内容 → 找 3 个隐藏关联 + 总结思考模式 + 提炼 1 个值得深思的问题 → 生成 brief。每周复盘输出四样：**核心观点/认知矛盾/知识缺口/最高杠杆一件事**。
- **优点**：知识缺口显性化（每周必查"体系缺什么"）；"最高杠杆一件事"直指行动。
- **缺点**：只做"简报"不做"行动追踪"——有提炼无执行闭环。
- **启发**：①每周必输出"知识缺口"（指导收集方向）；②每周只推"最高杠杆一件事"。

### 5. OpenClaw PKM 全家桶
- **是什么**：OpenClaw 的 PKM 技能组合：knowledge-review（SM2 间隔复习）+ weekly-knowledge-report（周报）+ MCP 工具链。
- **核心工作流**：每天推 5 张知识回顾卡片（回复 1-5 打分）；每周五生成知识管理周报：新增笔记数/高频标签/**知识缺口**/建议下週关注方向。
- **优点**：周报四要素固定格式，直接可抄；SM2 复习自动化。
- **缺点**：偏"复习记忆"，不偏"行动决策"。
- **启发**：周报四要素（新增数/高频标签/知识缺口/下週方向）。

### 6. CoPaw（开源个人 AI 助手工作站）
- **是什么**：AgentScope 框架的开源个人 AI 助手，多平台聊天 + 本地模型 + 技能系统。
- **核心工作流**：skills 定时任务（邮件摘要/周报/新闻追踪/知识库构建）。
- **优点**：开源 Apache 2.0、数据本地、可自由扩展——验证"本地优先"可行。
- **缺点**：通用助手，知识→行动闭环弱。
- **启发**：无强项，仅佐证本地化路线。

### 7. yolanda-skills（知识原子+定期回顾）
- **是什么**：Obsidian LLM wiki 管理 skill：信息输入 → 知识原子库 → 定期回顾 → 提炼专题 → **回写状态"已处理"**。
- **核心工作流**：触发回顾 → 扫描未处理原子 → 归类合并 → 提炼结构化专题 → 写入知识库 → 回写原子 status 为"已处理"。
- **优点**：**明确的状态回写机制**——"已处理"标记，防止重复提炼。这正是我们的记账本机制，写法都一样！
- **缺点**：只做知识沉淀，不做行动。
- **启发**：状态回写（记账本）是这个品类的标准答案，方向验证。

### 8. lightweight-kb（轻量知识库+任务管理）
- **是什么**：OpenClaw skill：user_profile.json（用户画像）+ task_rhythm.json（任务节奏）+ kb_index.json（知识索引）+ 每日自动进化。
- **优点**：用户画像与任务节奏分离存储；三层架构（宪法→法规→案例库）清晰。
- **缺点**：轻量级，能力有限。
- **启发**：目标/偏好与任务数据分离存储。

### 9. WorkBuddy 第二大脑案例（daily-task-board + 复盘）
- **是什么**：个人在 WorkBuddy 里养的技能组合（非产品，个人实践案例）。
- **核心工作流**：说"生成今日看板"→ 读昨天存档、未完成任务自动续入、连续未做超 3 天标红 → 交互网页（左侧完成率环形图+14 天趋势，右侧任务流）→ 收工保存三份：**JSON 给机器当唯一真相 + MD 给人读 + HTML 视觉快照**。复盘分五档：每日记忆卸载/每周节奏校准/每月目标问责/季度战略验证。
- **优点**：**三份输出**（JSON/MD/HTML）非常成熟；未完成任务自动续接 + 连续超 3 天标红（防拖延）；复盘自动读 JSON 填模板，人只写判断（零摩擦）；五档复盘节奏。
- **缺点**：个人实践，无产品化，需自己搭。
- **启发**：①三份输出（机器真相/人读/视觉）；②未完成自动续接 + 超时标红；③复盘自动填数据人只写判断；④日/周/月/季四档节奏。

### 10. OpenClaw Workboard 插件（官方）
- **是什么**：OpenClaw 官方看板插件：卡片 = 标题/状态（9 种）/优先级/标签/Agent/链接 + **事件流**（created/moved/linked/claimed/heartbeat...）。
- **优点**：卡片元数据精简设计；全事件流可审计（每张卡片的完整历史）。
- **缺点**：agent 任务管理，不是知识→行动。
- **启发**：事件流机制（append-only 全历史）佐证。

### 11. ima 知识库周报（腾讯 ima）
- **是什么**：定时（每周日）遍历知识库新增/修改文件 → 语义分块 → 向量化 → 生成周报 md + CSV 问答对（可导入 Anki）。
- **优点**：**增量扫描**（只看本周新增/修改）——和我们的扫描员机制一致；"知识从积灰变成可调用"。
- **缺点**：偏复习，不偏行动。
- **启发**：增量扫描（只处理新增/变更，旧内容不重复处理）。

## 二、共性结论（5 个竞品共同验证）

```
收集（蒸馏/订阅）→ 定期提炼（日简报/周复盘）→ 知识缺口分析
→ 行动项 → 看板展示 → 对话操控
```

- **看板只展示、操作靠对话** = 本品类标准形态（KimiClaw/Workboard/Panopticon/WorkBuddy 案例全中）
- **状态回写防重复** = 标准答案（yolanda "已处理"、OpenMontage checkpoint、Workboard 事件流）
- **知识缺口显性化** = 标配（Codex 周复盘/OpenClaw 周报/KimiClaw）
- **行动项有状态追踪** = 标配（待办/进行中/已完成）
- **我们与它们的差异（护城河）**：它们是通用知识管理，我们是**定向路线管理**——只收与五器项目/一人公司路线相关的内容，帮用户"管理一条路线"而非"管理所有知识"。

## 三、完整方案：「目标驱动·知识→行动回流系统」

### 3.1 五件套架构（代码固定、内容刷新）

```
D:\opus-magnum\wall\knowledge-actions\
├── goals.md              # ① 目标层（写一次，可更新）——你的长期目标+本周重点+决策原则
├── scan.py               # ② 扫描层（写一次，永不动）——增量扫描 Qdrant，对比记账本，输出新增/变更
├── state.json            # ③ 记账本（机器维护）——每份内容提炼状态+内容指纹+行动状态
├── template.md           # ④ 周清单模板（写一次）——固定格式
├── events.log            # ⑤ 事件流（append-only）——每周一条更新记录
└── weekly\               # 数据层（每周只更新）
    ├── 2026W33.md        # 本周清单（翻译官产出）
    └── ...
```

| 部件 | 轻重 | 实现 |
|---|---|---|
| ① 目标层 | 写一次可改 | goals.md：你的路线阶段 + 本周重点 + 决策原则（如"优先做能同时推动项目和变现的事"） |
| ② 扫描层 | 轻（~100 行脚本） | 对比 Qdrant 全部文档与记账本 → 输出"新增/变更"清单（ima 增量扫描思路） |
| ③ 记账本 | 中（一次性设计 schema） | 每份内容：doc_id/标题/内容指纹/提炼状态/行动状态（yolanda 状态回写 + WorkBuddy JSON 真相） |
| ④ 翻译官 | **我（对话），不写代码** | 读新增内容 → 按目标匹配 → 提炼行动项（Workboard 三段式：认知+依据+行动） |
| ⑤ 展示层 | 轻（模板固定） | Dashy 分区 + 巨作子页面，渲染每周 md |

### 3.2 每周更新流程（3 步，代码 0 改动）

```
你说"更新行动清单"（或每周一提醒）
  ↓
① 跑 scan.py（同一份代码）→ 挑出新增/变更文档
  ↓
② 我读新内容 → 对照 goals.md 目标 → 提炼行动 → 写 weekly/2026W33.md
  ↓
③ 记账本 state.json 记一笔 + events.log 留一条
  ↓
展示页自动显示最新一期
```

### 3.3 周清单模板（借鉴所有竞品精华）

```markdown
# 📋 本周知识→行动（2026W33）
一、新提炼行动（本周新增内容 → 按目标匹配）
   ☐ [高] 行动1：... | 来源：OKF | 依据：...
   ☐ [中] 行动2：... | 来源：仓颉skill | 依据：...
二、待办跟进（上周未完成，超 3 周标红 ⚠️）
   ☐ [高] 行动0：...（已提醒第 2 周）
三、🎯 本周最高杠杆一件事（只推一件）
四、🧭 知识缺口（你的路线需要、库里还没有）→ 建议下周收集方向
五、路线进度（目标层对照：本周推进了什么）
```

### 3.4 防重复/防 bug 机制（四重保险）

| 机制 | 借鉴自 | 作用 |
|---|---|---|
| 内容指纹 | OpenMontage checkpoint | 内容没变 → 跳过，绝不重复提炼 |
| 状态回写 | yolanda "已处理" | 提炼过的标"已处理"，机器为准非我记性 |
| 事件流 | OpenClaw Workboard | 每周一条日志，全历史可查 |
| schema 校验 | OpenMontage | 数据格式错当场报，坏数据进不来 |
