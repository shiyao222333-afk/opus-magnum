## 三、功能②：行动状态管理（已实施 ✅）

### 状态集合（4 档，用户拍板）

| 状态 | 含义 | 熔知写入 | 行动扫描 | 熔知检索 |
|---|---|---|---|---|
| 未动（默认） | 提炼过，还没行动 | — | 正常推荐 | 正常 |
| 📌 需深入 | 值得深挖，还没消化完 | — | **置顶重点推荐** | 正常 |
| ✅ 已完成 | 行动做完了，知识已吸收 | — | **跳过，不再推荐** | 正常（可查） |
| 📦 已归档 | 不再需要 | `is_archived=true` | **跳过，不再推荐** | **排除（查询时过滤）** |

### 状态存哪（用户拍板：熔知侧只用 is_archived 一个字段，不增殖）

```
熔知侧（检索可见）：is_archived（现成第6类字段，布尔）
  ├── true  = 📦 已归档 → 检索查询阶段直接排除
  └── false = 其余状态（默认）

行动系统侧（内部状态，不写熔知）：记账本 state.json docs[].status
  ├── need_deep  = 📌 需深入（置顶推荐）
  ├── done       = ✅ 已完成（跳过推荐）
  └── archived   = 📦 已归档（与熔知 is_archived=true 同步）
```

**为什么不新增熔知字段**：lifecycle 六档语义是"内容创作阶段"（想法→发布），不是"行动消化状态"，硬套会混淆；新开 ext 槽要改契约，增殖不值。is_archived 是现成的第6类字段，语义精确匹配"归档"。需深入/已完成是行动系统内部标记，熔知侧无对应语义，记记账本即可（用户拍板）。

### 状态写入路径（mark_status.py，已实施）

```
你在对话里说："XX 完成/归档了"（或我帮你执行）
   ↓
python mark_status.py <doc_id> <status>
  need_deep   → 只记记账本 status=need_deep
  done        → 只记记账本 status=done
  archived    → 写熔知 is_archived=true（set_payload key-level merge）+ 记账本记 archived
  unarchive   → 写熔知 is_archived=false + 记账本清状态（可撤销）
  每步：写后读回确认（防静默失败）；doc_id 不存在当场报错；重复标记幂等
   ↓
下次扫描：done/archived 自动跳过；need_deep 置顶
下次检索：archived 查询时排除（must_not）
```

**重摄入覆盖**：按用户确认，正常不会重摄入，风险降级不处理（已知限制）。

## 四、功能③：熔知检索排除（已实施 ✅，查询时过滤）

### 代码实证（已查）

熔知 `search_engine/core.py`：
- `search(query, facet_filter=..., exclude_archived=...)` → `_build_qdrant_filter()` 构建 `{"must": [...], "must_not": [...]}`
- **filter 直接传给 Qdrant query 接口** → **查询阶段过滤（pre-filter）**，不是搜完再滤 ✅

### 已落地改动

```python
# _build_qdrant_filter(facet_filter, exclude_archived=False)
#   exclude_archived=True → must_not: [{"key": "is_archived", "match": {"value": true}}]
#   无 facet_filter 时也能独立生成 must_not（仅排除）
#   warnings 返回"已排除归档内容（is_archived=true）"便于确认

# search() / answer() 增加参数 exclude_archived=False（默认不排除，显式传 True 排除）
# UI 搜索页 pages/search.py：三处调用全部传 exclude_archived=True（LLM问答/普通搜索/灵感浮现）
```

- Qdrant 原生支持 must/must_not，索引内过滤，性能无影响
- **防静默失效**：结果里若仍出现 is_archived=true 的点 → warnings 告警"归档排除疑似失效"
- **黑名单方案已砍**：原方案的 exclude_doc_ids 黑名单参数被 is_archived 单字段替代（用户拍板），熔知 UI 只排除 is_archived 字段，不读 action-flow 文件（避免跨项目耦合）

## 七、边界与风险

- **不新增熔知字段**：状态只用 is_archived（现成字段），需深入/已完成记记账本（行动系统内部），符合"统一不增殖"
- **重摄入覆盖**：按用户确认不作为问题（正常不重摄入，已知限制）
- **播放≠唯一标准**：只作推荐权重，最终按目标决策
- **跨项目**：熔知检索层改动已最小化（must_not 支持），不影响摄入/分类
- **已完成 vs 归档的区别**：已完成=知识已吸收、行动不再推、但保留可查；归档=彻底不要、检索也看不见
