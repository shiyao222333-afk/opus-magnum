# 项目反哺调研规范（RESEARCH-GUIDE）

> 用途：行动清单「项目反哺」条目的深度调研执行标准。自动化任务（定时）与对话手动触发共用同一套流程。
> 输入：`weekly/` 最新清单「### 🎯 项目反哺」分区下的全部条目（按项目分小节）。
> 输出：`pending/` 待审批清单（有价值条目）+ 记账本状态标记（need_deep / archived）。

## 调研步骤（对每条行动项）

1. **读条目**：取 标题、依据、doc_id、所属项目。
2. **读熔知文档内容**：用 doc_id 查 Qdrant（`scroll filter doc_id`），读 title / auto_summary / 关键正文段落，理解条目说的到底是什么。
3. **进网页看原文（如有）**：取该文档 `origin.source_url`；若是文章/博客/教程页 → WebFetch 看原文要点；若是 B站视频页（反爬拿不到正文）→ 以熔知文档内容为准，跳过网页。
4. **对照项目能力**：看对应项目现状（README / 关键代码 / 已有功能），判断"这条能不能用、怎么用"。
5. **审核改动风险**：如果实施这条，要改什么、会不会影响现有功能、有没有更简单的替代。分三档：
   - 🟢 低风险：新增/独立改动，不影响现有功能
   - 🟡 中风险：改动现有模块，需回归
   - 🔴 高风险：动核心链路/数据契约，需谨慎论证

## 价值判定

| 判定 | 条件 | 动作 |
|---|---|---|
| ✅ **有价值** | 与项目方向相关 + 可落地（对照后能实施）+ 风险可接受 | 标 `need_deep` + 写入待审批清单 |
| ❌ **没价值** | 与项目无关 / 已被现有功能覆盖 / 技术栈不匹配 / 风险过大 | 标 `archived`（归档，不再推荐） |
| ⏸️ **暂缓** | 方向相关但时机不成熟 / 依赖未就绪 | 标 `need_deep` 也可，但待审批条目注明"暂缓原因" |

**去重**：与 `weekly/` 全部既有条目、`pending/` 已有未决条目、记账本 archived 记录对比——标题/来源相同的不重复生成。

## 输出格式

### 待审批清单条目（`pending/待审批-2026WXX.md`，结构对齐行动清单）

```
- [ ] 🔴 **{可执行行动标题}** | 项目：{项目名} | 方向：{方向} | 来源：{来源文档标题} | 依据：{一句话理由} | 调研：{网页要点/对照结论} | 风险：{🟢低/🟡中/🔴高} | 创建周：WXX | 优先：{高/中/低} | doc_id：{熔知文档ID}
```

### 记账本动作

- 有价值 → `python mark_status.py <doc_id> need_deep`
- 没价值 → `python mark_status.py <doc_id> archived`

### 调研报告（对话/任务输出）

按项目分组汇报：调研了哪几条、各判定结果（有价值/没价值/暂缓）、各风险档、待审批共几条。

## 审批流程（用户操作）

用户对待审批清单逐条说：`批准 1,3,5` → 把对应条目追加进 `weekly/` 最新清单对应项目小节（保留全部字段）；`打回 2,4` → 标 `archived`。已审批的待审批条目从 pending 文件移除或标注「已批准/已打回」。
