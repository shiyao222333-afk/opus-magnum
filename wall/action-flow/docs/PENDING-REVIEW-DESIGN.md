# 项目反哺 · 审核清单双账本设计（v3.4）

> 2026-08-04 定稿 · 用户确认后落地
> 相关任务：#452-#456

## 一、背景与目标

项目反哺调研自动化（每周一 9:00）需要一份**滚动更新的审核清单**：
- 每次固定调研 5 条（控制单次时长 ~50 分钟）
- 所有条目更新进**同一份**审核清单（不是每周新建文件）
- 用户审核完的条目**自动消失**（批准/打回后不再出现）
- 核对/去重**全部由记账本完成**（不靠 md 对账、不靠人工清理）

## 二、核心架构：两份账本，各管一件事

| 账本 | 位置 | 管什么 | 状态 |
|---|---|---|---|
| **行动清单记账本** | `wall/action-flow/state.json`（已有） | 知识条目**值不值得做** | 无状态（未调研）/ `need_deep` 值得做 / `archived` 归档 / `done` 已完成 |
| **审核清单账本** | `wall/action-flow/pending/state.json`（新建） | 调研结论**审核到哪一步** | `pending` 待审 / `approved` 已批准 / `rejected` 已打回 |

**边界**：审核清单账本只记"审核进度"，不记行动状态；行动清单账本只记"做不做"，不记审核进度。两者通过 doc_id 关联，互不覆盖。

调研笔记 `pending/items/{doc_id}.md` 是**纯内容附件**（原文要点/网页查证/任务拆解），不含任何状态——状态一律只进两份账本。

## 三、主流程（一条链走通）

```
scan.py 扫描新条目（读行动清单记账本去重：archived/done 跳过、need_deep 置顶）
   └→ 行动清单记账本：无状态（= 未调研候选）
        ↓ 自动化调研（每次 5 条，串行，子任务不写任何账本）
       ┌──────────────────────────────┐
       │ 没价值          │  有价值      │
       ▼                ▼
  行动清单: archived      行动清单: need_deep（值得做，置顶推荐）
  （直接归档，            审核清单: pending（待用户审核）
   不进审核清单）         调研笔记: items/{doc_id}.md（纯内容）
        ↓ 用户审核（对话说「批准 X / 打回 X」）
  批准 ──→ 审核清单: approved（清单里消失）
          + 反哺行动清单：保持 need_deep → 进入执行 → 完成标 done
  打回 ──→ 审核清单: rejected（清单里消失）+ 理由记 feedback-log.md
          + 反哺行动清单：标 archived（不再推荐、不再被调研）
```

## 四、反哺规则（防两本账分裂）

审核结论**必须写回行动清单记账本**，否则下次扫描会重复推荐：

| 场景 | 不反哺的后果 | 反哺动作 |
|---|---|---|
| 打回 | 行动清单仍 need_deep → scan 置顶 → **下周一又被调研一遍** | 行动清单标 `archived` |
| 批准 | 行动清单不知道已采纳 → 状态停滞 | 保持 `need_deep` 进入执行，完成标 `done` |
| 调研没价值 | —（本来就没进审核清单） | 行动清单直接标 `archived` |

## 五、关键区分：「调研判没价值」≠「用户打回」

两者最终都落在行动清单 `archived`，但语义不同：

| | 谁判的 | 是否进审核清单 | 痕迹 |
|---|---|---|---|
| 没价值 | 自动化调研 | ❌ 不进（用户看不到） | 行动清单 archived |
| 打回 | 用户审核 | ✅ 进过，标 rejected | 审核清单 rejected + feedback-log 记理由（可能"有价值但时机不对/太复杂/优先级低"） |

## 六、审核清单页面（serve.py /pending）

- 不再读待审批 md，改为：**读审核清单账本 `pending` 条目 → 每条拼 `items/{doc_id}.md` 详情 → 渲染**
- 管理栏按钮复用现有 `/api/action`（action=archive 已存在；approve 需新增，落地时定）
- 状态一变（approved/rejected/archived）→ 刷新即消失 = 「审核完自动去掉」
